# 头顶对话气泡接口（speak_api）

让游戏里**任意单位**以**任意身份**头顶弹出对话气泡；多个单位可以同时说话；每个气泡的大小、字号、颜色等都能单独定制；
能直接接本地大模型，一句话进、一句回复出在单位头上。

| 组件 | 位置 | 作用 |
|---|---|---|
| DLL 动作 56 | 运行时里；打包格式见 `sdk/python/w3speak.py` | 在游戏画面里画气泡 |
| Python 客户端 | `sdk/python/w3speak.py` | 打包批量请求、发给 DLL |
| HTTP 接口 | `speech/speak_api.py`，启动 `speech/start_speak_api.ps1`，默认 `http://127.0.0.1:8872/`（端口在 `openwar3.json` 的 `ports.speech`） | 给任何程序调用；界面在远见「头顶气泡」页（8872 根地址跳过去） |
| 测试 | `sdk/python/tests/test_w3speak.py` | 打包格式逐字段核对 |
| 农民茶话会 | `speech/banter.py`，测试 `speech/tests/test_banter.py` | 家里的工人按人设互相吐槽、开局报幕 |
| 镜头对白 | `speech/camtalk.py`，测试 `speech/tests/test_camtalk.py` | 镜头里的英雄（首领口吻）和随从（随从口吻）说话，不显示名字 |
| 战况触发 | `speech/eventtalk.py`，测试 `speech/tests/test_eventtalk.py` | 开战/打完/英雄阵亡/升本/被拆……出事了才说 |

⚠ 换了 DLL 以后，**已经在跑的游戏进程还是旧 DLL**，要等那个实例下一局重开游戏进程才生效；没有气泡功能的旧 DLL 调接口会回 409。
气泡要的绘制钩子只在第一次说话时才装，不说话的实例行为不变。09-25 起气泡和旁白框画在鼠标指针下面（和画板同一处）。

## 接口

所有请求用 `pid`（游戏进程号）或 `inst`（实例号，War3-16.exe 就是 16）指定哪个游戏；只有一个游戏在跑时可以都不给。

### 让单位说话 `POST /api/say`

```json
{
  "inst": 16,
  "bubbles": [
    {"unit": "0x14A12614", "name": "山丘之王", "text": "跟我冲！"},
    {"unit": "0x14A12924", "name": "大法师", "text": "我来放暴风雪。",
     "style": {"font_px": 26, "text_color": "#FFE080", "bg_color": "#C0102040"}},
    {"screen": [960, 110], "key": 1, "name": "旁白", "text": "第一波兽人还有 30 秒到达。",
     "style": {"tail": false, "type_ms": 0}},
    {"world": [-4684, 2644], "key": 2, "text": "集合点", "style": {"font_px": 16}}
  ]
}
```

每条气泡的字段：

| 字段 | 说明 |
|---|---|
| `unit` / `world` / `screen` | 三选一。`unit` = 单位地址（`/api/units` 里的 `unit`），跟着单位走，有血条时贴在血条正上方；`world` = 地图坐标 `[x, y]`；`screen` = 屏幕像素 `[x, y]`（气泡尖的位置，旁白用，画在界面最上层） |
| `name` | 第一行显示的说话人。随便写，不必是这个单位（「以任何人的身份」） |
| `text` | 正文，自动换行 |
| `duration_ms` | 显示多久；0 = 自动 **3~5 秒**（打字时间 + 1.5 秒，夹在 3~5 秒；长句自动加快打字，保证在 60% 的时间里打完）。给了就照给的来 |
| `key` | 世界/屏幕气泡的编号：同 key 的新消息顶掉旧的；0 = 每次新开一个 |
| `update` | true = 已有同一个气泡（同单位 / 同 key）就只换文字和样式，不重置计时，打字从当前进度接着打（流式输出用） |
| `remove` | true = 删掉这个单位 / 这个 key 的气泡 |
| `lift` | 给了就不贴血条，按世界单位抬这么高 |
| `style` | 见下表 |

同一个单位只留一个气泡，新话顶掉旧话。几个单位挤在一起同时说话时**默认就叠着**（场上同时说话的人不多、一句只显示 3~5 秒）。
想让它们自动让开：`POST /api/config {"avoid_overlap": true}`（或调试页勾「避免遮挡」）—— 气泡主体往侧面/上面挪，
**尾巴斜着拉长指回说话的单位**（不画引线）。这个开关存盘，已经连过的实例立刻生效，之后新连上的实例也会先设好。

### 样式 `style`

| 字段 | 默认 | 说明 |
|---|---|---|
| `font_px` | 0 = 自动（屏幕高 x 0.021，1080p 约 22） | 正文字号（像素） |
| `name_font_px` | 0 = 正文 x 0.8 | 名字字号 |
| `max_width_px` | 0 = 正文字号 x 14 | 正文最大宽度，超了换行（**气泡大小**主要由它和字号决定） |
| `pad_px` / `radius_px` | -1 = 自动 | 内边距 / 圆角（0 = 直角） |
| `border_px` | -1 = 自动（1.6） | 边框粗细，0 = 不画 |
| `text_color` / `name_color` / `bg_color` / `border_color` / `shadow_color` | 浅白 / 金 / 半透明深蓝黑 / 暗金 / 黑 | 颜色：`#RRGGBB`、`#AARRGGBB`、`#RGB`、`rgba(r,g,b,a)`、`gold` 等英文名 |
| `tail` / `shadow` / `fade` | true | 小尾巴 / 正文阴影 / 最后 0.6 秒淡出 |
| `type_ms` | 45 | 逐字打出每个字几毫秒，0 = 一次出全 |
| `side_px` | 0 | **气泡往侧面偏**（右正左负），尾巴尖仍钉在单位头上、尾巴斜过去；偏得多时自动尾巴会跟着变长（至少是横向差距的一半），不会斜成一根横线 |
| `tail_len_px` | -1 = 自动（正文字号 x 0.65） | 尾巴长度；给了就固定这个长度 |
| `opacity` | 1.0 | **整个气泡（连文字）的不透明度** 0~1；底色自己的透明度是 `bg_color` 的 alpha，两者相乘 |
| `offset_x` / `offset_y` | 0 | 放好之后整体再挪的像素（右、下为正；尾巴尖也跟着挪，就不指着单位了 —— 想偏到侧面用 `side_px`） |
| `font` | 微软雅黑 | 字体名（系统里有的字体） |

### 其它

| 接口 | 说明 |
|---|---|
| `GET /api/instances` | 在跑的游戏 `[{pid, inst, exe}]` |
| `GET /api/units?inst=16&mine=true&heroes=true&type=hpea&owner=0` | 单位列表：`unit`（地址）、`type`、`name`（中文名）、`owner`、`mine`、`hero`、坐标、血量 |
| `POST /api/clear` `{inst[, unit | key]}` | 清掉一个或全部 |
| `GET /api/status?inst=16` | DLL 统计：画了几帧、每帧多花多少微秒等 |
| `POST /api/chat` | 见下 |
| `GET /api/llm`、`POST /api/llm` | 看 / 改模型配置（`base_url`、`model`、`mode`、`max_tokens`、`temperature`），改动存进 `speak_api.json` |
| `GET /api/config`、`POST /api/config` `{avoid_overlap[, inst]}` | 气泡全局开关（目前只有「避免遮挡」，默认关），存进 `speak_api.json` |

### 和本地模型对话 `POST /api/chat`

```json
{"inst": 16, "unit": "0x14A12614", "name": "山丘之王",
 "persona": "你扮演魔兽争霸里的山丘之王穆拉丁，豪爽、爱喝酒。一两句口语，不超过40个字。",
 "message": "前面有一群食人魔，我们冲不冲？", "stream": true, "style": {"font_px": 24}}
```

返回 `{"reply": "...", "first_token_ms": 283, "total_ms": 342}`，同时这句回复已经出现在那个单位头上。
`stream=true` 边生成边更新气泡；同一个单位会记住最近 6 轮（`conversation` 可以自定义会话 id，`reset: true` 清空记忆）。

### 农民茶话会 `POST /api/banter`（`banter.py`）

家里（主基地 1800 以内）的工人各自分到一个人设，用本地模型轮流说一句，互相吐槽「天天被 AI 拉来开局挖矿当训练数据」；
每局开局由报幕担当报「第几局、今天第几局、几胜几负、上一局怎么没的」。调试页最下面「农民茶话会」一栏就是它。

```json
{"inst": 5, "enabled": true, "interval_s": 7, "max_chars": 32, "stats_inst": 0, "pro_every": 3,
 "duration_s": 6, "font_px": 26, "name_font_px": 20}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | — | true 开、false 关（开 = 把这个实例加进自动开启表，见下面「自动开启」；设置都存进 `speak_api.json`） |
| `interval_s` | 7 | 两句之间大概隔多久（随机 ±30%，且至少等上一句显示完） |
| `max_chars` | 32 | 每句最多几个字（报幕多给 16） |
| `stats_inst` | 0 = 跟游戏同一个实例 | 战绩从哪个实例的对局记录读。测试实例没有战绩时填 5 |
| `pro_every` | 3 | 每几句带一次高手名字（Sky、Moon、Grubby、TH000、Infi、Fly100%、Lyn、Happy、120、Ted、ToD、Remind、Lawliet、FoCuS 轮换） |
| `duration_s` | 0 = 自动（按字数 3~5 秒） | 每句显示几秒（1~30）。下一句至少等这句显示完才说 |
| `font_px` / `name_font_px` | 0 = 自动 | 正文字号（1080p 自动约 22）/ 名字字号（自动 = 正文 x 0.8） |
| `home_radius` / `temperature` | 1800 / 0.95 | 家的范围 / 模型温度 |

网页上这些设置改了就存、开着的茶话会从下一句起生效。茶话会按**实例号**跟着走：实例每局重开游戏进程（pid 会变），
茶话会自己跟到新进程上、新一局报幕（09-18 以前按 pid 存，打完一局就悄悄停了）。

* `POST /api/banter/poke {"inst":5, "topic":"弹幕：你们什么时候能赢一把"}` —— 抛话题（转弹幕），下一句就接它
* `POST /api/banter/announce {"inst":5}` —— 马上报一次幕；`GET /api/banter?inst=5` —— 人设、心情、最近 30 句台词、当前喂给模型的战况

怎么保证「像真的」：
* **战况全是真数据**：场次/今天第几局/胜负来自 Farsight（8866，没开就直接读 `build_intel4/inst<N>/matches`）；
  上一局写明结局、分钟数、双方兵力峰值、升本、大厅数；现在的库存、人口、家里几个工人在挖金/砍树/闲着；敌人打到家门口会触发「敌袭」一句。
  报幕只许用这些事实（09-18 实测：不限制时模型会编「那波一波流」）。
* **12 个固定人设**（小美报幕担当、老王老油条、小李 00 后、铁柱卷王、翠花毒舌、老张怀旧 Moon 粉、阿强阴谋论、二狗憨憨、
  大壮兽族卧底、老刘佛系、阿飞吹牛 TR 过 Sky、秀才半文半白），各带心情（暴躁…亢奋），开新局大家更丧一点，说完随机飘。
* **高手梗不出错**：提到谁就把他那个种族的英雄兵种表一起给模型（09-18 实测：只给「韩国暗夜精灵传奇」时说出「Moon 的蜘蛛」）。
* **不复读**：话头在 10 个角度里轮换；最近 6 句用过的网络梗（好家伙、牛马、下次一定……）下一句点名禁用。
* 工人进金矿时会从快照里消失 —— 人设按最后一次见到保留 90 秒，不会误报「某某没了」。

⚠ 09-18 在 16 号测试实例上验过；5 号要等它换上新 DLL 的游戏进程（见开头）。

### 镜头对白 `POST /api/camtalk`（`camtalk.py`，调试页「镜头对白」一栏）

**镜头里**的人说话：画面里有英雄 -> 英雄用首领口吻说一句、离他最近的随从接（`replies` 句）；没英雄 -> 两个兵聊两句。
**气泡不显示名字**，只用边框颜色区分：首领金边、随从灰蓝、敌方英雄红边。工人和建筑不参与（工人归茶话会）。

* 谁在画面里：读镜头（GetCameraTargetPosition / GetCameraField，走进程内通道），用 `war3-analytics/camframe.py` 的投影
  （和导播同一套，09-18 对着截图标定过）；敌人和野怪还要过迷雾检查（IsVisibleToPlayer）—— 快照里有迷雾里的单位，
  09-18 实测右下黑乎乎的一片里有 4 个两栖怪，不查就会说「在打野」。
* 现场事实：交战 / 打野 / 在家 / 行军、英雄血量、随从整体血量、刚才掉了多少血、库存人口。
* 英雄按魔兽世界观的性格说话（大法师睿智、山丘之王豪爽爱喝酒……）；首领每轮换一种说法（下令/判断局势/鼓舞/敲打……），
  随从每句换一种态度（领命/拍马屁/紧张/求战/嘀咕/自夸……）—— 不换的话随从三句都是「大人放心」。
* 参数：`interval_s` 10、`duration_s` 0（自动）、`font_px` 0、`max_chars` 24、`replies` 1、`include_foes`（敌方英雄放狠话）、`extra`（额外要求）。
* `GET /api/camera?inst=5`：调试用，镜头在哪、画面里有谁、看不看得见（不说话）。
* 战况触发正在说的时候，镜头对白这一轮让一让（同一个英雄头上只能有一个气泡）。

### 战况触发 `POST /api/events`（`eventtalk.py`，调试页「战况触发」一栏）

不再只按间隔说：每秒和上一秒比，**出事了**才让相关的人说，默认只挑镜头里的人（`only_in_view`）。

| 事件 | 怎么认 | 谁说 |
|---|---|---|
| 开战 | 双方各 ≥ `fight_min` 个作战单位 600 以内 | 参战的我方英雄喊（`include_foes` 时敌方英雄先放狠话），兵接 |
| 一仗打完 | 脱离接触 6 秒；双方各倒下几个（快照里不见 = 死了，迷雾不影响） | 活着的英雄总结，兵接 |
| 打野 | 英雄 600 以内有掉血的野怪，同一营地 120 秒一次 | 英雄 |
| 英雄残血 / 阵亡 / 复活 | 血量跌破 `hero_low_pct`% / 连续 2 秒不见 / 又出现 | 英雄自己 / 旁边的兵或农民 / 英雄 |
| 升本 / 开分矿 | 大厅类型升级 / 新大厅 | 大厅边上的农民（升本英雄也说） |
| 建筑被拆 | 建筑没了且 1200 以内有敌人（取消的地基不算） | 旁边的人 |
| 家被打 | 大厅 1300 以内 ≥ 2 个敌方作战单位 | 农民 + 守军 |
| 一下死一片 | 20 秒内我方倒下 ≥ `big_loss_n` 个 | 英雄 |
| 人口到坎 | 人口过 50 / 80（维护费） | 英雄或农民 |

出事的人不在镜头里（09-18 空跑：英雄阵亡、升本、复活都发生在镜头外）时，`bystander`（默认开）让**镜头里的自己人**
当旁观者「听说了」说一句，观众照样看得到反应；关掉就跳过。
每种事件能单独开关、单独冷却（`enabled_events` / `cooldowns`）；一堆事同时发生按优先级挑（英雄阵亡 > 死一片 > 家被打 > 开战 > ……），
其余排队，过了 `min_gap_s` 再说，8 秒还没轮到就作废（日志里写「让给了更要紧的事」）。网页上的日志逐条写认出了什么、说了没有、为什么没说。

### 自动开启 `GET/POST /api/autostart`

```json
{"banter": "5", "camtalk": [5], "events": "5,7"}
```

三个功能各一张实例号表：表里的实例只要在跑、功能没开，看门线程 **5 秒内**就把它开起来 ——
接口重启、游戏每局重开进程（pid 变）、实例晚一点才起来都接得上。网页上按「开」= 加进表，按「关」= 去掉；
也可以直接在各栏的「自动开启实例号」里填。存在 `speak_api.json`。

### Python 直接调（不经 HTTP）

```python
import w3speak
sp = w3speak.Speaker(pid)
sp.say([w3speak.Bubble(unit=0x14A12614, name='山丘之王', text='跟我冲！', style=w3speak.Style(font_px=26, side_px=120))])
```

## 本地模型怎么选（09-18 在这台 RTX 5090 上实测，5 句游戏台词）

| 模型 | 显存 | 速度 | 一句回复 | 结论 |
|---|---|---|---|---|
| **Qwen3.6-35B-A3B（MoE，每次只激活 3B），Q4，关思考** | 20.6 GB | 约 142 token/s | **约 0.3 秒**（首字约 0.27 秒） | **推荐**：快、中文角色扮演自然 |
| gpt-oss-20b（MXFP4），推理 low | 11.3 GB | 约 280 token/s | 0.3~0.8 秒 | 显存紧时用，中文略平 |
| Qwen3.6-27B（稠密），Q4 | 17.2 GB | 约 39 token/s | 5.5 秒还在思考 | 不适合实时对话 |

要点：
* **速度看「每次激活的参数量」，不看总参数**：35B 的 MoE 只激活 3B，比 27B 稠密快 3~4 倍。
* **必须关掉「思考」**：Qwen3.6 默认先思考，LM Studio 不理 `/no_think` 和 `enable_thinking=false`，
  不关的话 200 个 token 全用在思考上、一个字都没回。接口的 `qwen-nothink` 模式用补全接口手工拼 ChatML、预填空的 `<think></think>` 解决。
* 气泡逐字打出是每秒约 22 个字，模型每秒 100 多个 token，所以生成速度已经不是瓶颈，真正影响体验的是首字延迟（约 0.3 秒）。

## 实测事实

* **09-19 起所有气泡都在 Present 时最后画，盖在血条上面**（对局画面：气泡被别的单位的血条挡住了）。
